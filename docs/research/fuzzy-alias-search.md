# Research: fuzzy and alias matching for icon search

Date: 2026-10-08. Status: research only, no code changed.
Placement: `docs/` has ADRs (`docs/adr/000N-*.md`) but no research-notes folder. This is research, not a
decision, so it lives in `docs/research/`. If the recommendation is accepted, record it as `docs/adr/0006-*.md`.

**Complaint:** `k8s` does not find Kubernetes services (EKS etc.), `es` does not find Elasticsearch/OpenSearch,
and `postgres` does not find PostgreSQL (RDS/Aurora). The ask is smarter search so the domain skills pick the
right icons.

Follow-up (Rust/WASM libraries under the Bun build): see [`fuzzy-rust-libs-bun.md`](fuzzy-rust-libs-bun.md).

**Short version:** the kit already has a 7-entry shorthand map and an unused per-entry `aliases` hook. The real
problems are (1) the map is too small and *replaces* the token instead of adding to it, (2) any substring match
scores, so short tokens are noisy, (3) vendor words (`aws`/`azure`/`gcp`) are scored like content words, and
(4) there is no typo tolerance. A zero-dependency fix of about 100 lines plus one alias data file covers every
example below.

## 1. How search works today (primary source)

### Catalog loading
- `loadCatalog(path = catalog/aws.json)` reads the base file, then merges **every** sibling `catalog/*.json`
  (icons, groups, categoryColors). Each entry gets a `pack` field. It builds `byName` (a Map) and the
  `validNames` set — `src/core.mjs:15-41`.
- Size: 2,168 entries in `byName` (measured, see §2). The README says 2,106 icons — `README.md:211`.
- Note: because of the sibling merge at `src/core.mjs:27-34`, any new `catalog/*.json` gets loaded as a pack.
  So an alias file must **not** go in `catalog/` unless it follows the pack schema.

### Entry fields
Measured over all 12 catalog files (node one-liner, §2):
- Fields on every icon: `name, label, category, color, w, h, tags, style`. Non-AWS packs also have `src`.
- **No entry has `aliases` or `keywords` (0 of 2,168).**
- `tags` is a single string, not an array:
  - AWS: copied verbatim from draw.io's own sidebar tags, e.g. `"aws4 elastic container service eks for kubernetes aws amazon web service container containers  Elastic Kubernetes Service"`.
    Built by `scripts/ingest_index.py:75` from `data/shape-index.json.gz`.
  - Azure/GCP: generated by the pack builder, e.g. `"kubernetes services compute azure kubernetes services"`.
  - OSS packs: hand-written in the manifest, e.g. database `postgres`: `"postgres postgresql relational oltp sql rdbms"`.
  - Source: `scripts/build_pack.py:159-162`. That code passes through only `tags`, never `aliases`.

### Scoring and search
- `norm()` lowercases, applies NFKD, maps non-`[a-z0-9]` to spaces, and trims — `src/core.mjs:43-49`.
- `scoreEntry()` — `src/core.mjs:51-73`:
  - Haystack = `name + label + category + tags + aliases + keywords` (`:54-56`). So the scorer already reads
    `entry.aliases` / `entry.keywords`, but nothing fills them.
  - +100 if the whole query equals the name; +60 if it equals the name with spaces removed (`:58-59`).
  - Per token: +25 for a whole-word match in the name, **else +12 for a substring anywhere in the name**
    (`:61-62`), plus **+6 for a substring anywhere in the haystack** (`:63`).
  - +30 head-noun boost on the last token (`:68-72`).
- `QUERY_ALIASES` (`src/core.mjs:75-80`) is a 7-entry whole-token map: `k8s→kubernetes, psql/pg→postgresql,
  es→elasticsearch, mongo→mongodb, rabbit→rabbitmq, hashicorp→"hashicorp vault"`. It was added in commit
  `3be6034` ("fix(search): expand shorthand aliases…"). The comment there says "Whole-token expansion here beats
  editing 12 catalog JSONs."
- `searchIcon()` swaps each token for its alias (**replace, not add**). It then filters by `kind` and
  `category`, keeps score > 0, sorts, and slices to `limit` (default 8) — `src/core.mjs:83-100`.
- Search output is compact by default (`name,label,category,kind,color`). `--full` adds `aliases`, `style`, and
  `score` — `src/core.mjs:105-136`.
- There is no `pack`/vendor filter option, even though entries carry `pack` (`src/core.mjs:19`).

### Callers
- CLI `drawio-ai search <q>[, <q>…] [--category] [--limit] [--kind] [--full]`. Commas switch to batch mode
  (`src/cli.mjs:58-74`). It loads the catalog once (`src/cli.mjs:56`).
- The validator suggests names for an unknown stencil with `searchIcon(name.replace(/_/g," "), {limit:3})` —
  `src/core.mjs:216`. Better search also improves these "did you mean" hints.
- `builder.icon()` throws `Icon not found … use search_icon` — `src/builder.mjs:57`, `:77`. That is a stale
  name: the MCP tool was removed (`docs/adr/0002-cli-only-remove-mcp.md`). The real command is `drawio-ai search`.
- In-process use is documented in `src/cli-lib.mjs:155`.

### How the skills tell the AI to look up icons
- Every domain skill says, at step 3: "Look up every icon with ONE batched `drawio-ai search "a, b, c"`; never
  recolor icons." Its checklist says "Every icon came from `drawio-ai search`". See
  `skills/drawio-aws/SKILL.md:57,131`. azure/gcp/databricks/bpmn have the same lines (`:57`, `:130/131/138`).
- The skills give no advice on query phrasing (vendor prefix, full names vs shorthand). So the agent types
  whatever it has, usually shorthand.

### Existing tests
- `test/core.test.mjs:79-82`: `kubernetes` must include `eks`.
- `test/core.test.mjs:84-87`: `k8s` must include `kubernetes`, and `pg` must include something matching `/postgres/`.
- `test/core.test.mjs:90-95`: head-noun regressions (`gateway vpc endpoint` → `endpoint`, `nat gateway` → `nat_gateway`).
- `docs/developer-guide.md:84,148` documents `searchIcon(catalog,q,{category,limit,kind})` and says it is covered by tests.

## 3. Data that could power aliases

**draw.io's own tags carry long-form synonyms but almost no shorthand.**
- Upstream sidebar entries pass a tag string through `getTagsForStencil(pkg, stencil, moreTags)`, e.g.:
  - OpenSearch: `'opensearch open search service elasticsearch'`
  - EKS: `'elastic container service eks for kubernetes eks cloud'`
  - Source: [Sidebar-AWS4.js L324-325](https://github.com/jgraph/drawio/blob/96f8c7acb719aa93f0108eecedf20c3afdcbe431/src/main/webapp/js/diagramly/sidebar/Sidebar-AWS4.js#L324-L325) and [L888](https://github.com/jgraph/drawio/blob/96f8c7acb719aa93f0108eecedf20c3afdcbe431/src/main/webapp/js/diagramly/sidebar/Sidebar-AWS4.js#L888).
  - `getTagsForStencil` splits the package name and converts `_` to spaces ([Sidebar.js L6332-6349](https://github.com/jgraph/drawio/blob/96f8c7acb719aa93f0108eecedf20c3afdcbe431/src/main/webapp/js/grapheditor/Sidebar.js#L6332-L6349)).
  - The kit's vendored index keeps these strings verbatim (`scripts/ingest_index.py:75`).
- Scan of all 10,446 entries in `data/shape-index.json.gz` (tags + title):
  - `\bk8s\b`: **0** hits. `\bes\b`: **0**. `\bpg\b`: **0**. `\bgcs\b`: **0**.
  - `elb` appears only in `aws3d` tags.
  - `gke`/`aks` appear only on GKE On-Prem and on the AKS-* sub-icons.
  - The useful long forms that do exist: "elastic search", "big query", "postre sql" (sic), "application
    programming interface", "mongo db".
  - Upstream data has typos too: `postgresql_instance` tags read `"aws4 postresql instance …"` (also in `catalog/aws.json`).
- **Conclusion:** shorthand aliases (k8s, es, pg, apigw, ddb, gcs, elb/alb, gke/aks, vnet, msk) are not in any
  upstream data. They must be hand-curated. A curated list of about 60–100 entries covers the common cloud
  shorthand.

**What draw.io's sidebar search does (prior art, zero-dependency, written for the same shapes):**
- **Inverted tag index:** `addEntry` lowercases tags, splits on space and `/,()`, and indexes each tag. It also
  indexes a **Soundex** form of each tag with trailing digits removed. Tags shorter than 2 characters are
  ignored. Source: [Sidebar.js L1260-1335](https://github.com/jgraph/drawio/blob/96f8c7acb719aa93f0108eecedf20c3afdcbe431/src/main/webapp/js/grapheditor/Sidebar.js#L1260-L1335).
  Soundex is implemented at [Editor.js L982](https://github.com/jgraph/drawio/blob/96f8c7acb719aa93f0108eecedf20c3afdcbe431/src/main/webapp/js/diagramly/Editor.js#L982).
- **Partial matches:** a match at a word boundary inside a tag counts as "prefix". A match mid-word counts only
  when the term has **≥ 4 characters** (`minInnerLength = 4`, "to avoid noise"). Source: [Sidebar.js L1432-1470](https://github.com/jgraph/drawio/blob/96f8c7acb719aa93f0108eecedf20c3afdcbe431/src/main/webapp/js/grapheditor/Sidebar.js#L1432-L1470).
- **Tiered scoring:** "+1.0 per exact match, +0.8 per match at a word boundary in a tag, +0.6 per match inside
  a tag, +0.5 per Soundex-only match", best tier once per term. It tries AND across terms first and falls back
  to OR. Source: [Sidebar.js L1634, L1743-1781](https://github.com/jgraph/drawio/blob/96f8c7acb719aa93f0108eecedf20c3afdcbe431/src/main/webapp/js/grapheditor/Sidebar.js#L1743-L1781).
- This is the same tier order recommended below, minus aliases. The ≥4-character rule for mid-word matches is
  exactly what fixes the `lb`/`nat`/`es` noise seen here.

## 4. Approaches, smallest first

Constraints: `package.json` has **no `dependencies`**. The CLI is described as zero-dependency (`package.json`
description; `src/core.mjs:1-3`; `CLAUDE.md` "No bundler… Plain .mjs only"). The catalog is small: 2,168
entries and a **1,828-token vocabulary** (measured). A brute-force Damerau-Levenshtein scan of the whole
vocabulary takes **≈2 ms** per query term (measured, Node 22). No index structure is needed.

### (a) Hand-curated alias map
- **What:** shorthand → targets. Either (i) a query-term map (what `QUERY_ALIASES` is now), or (ii) entry-keyed
  aliases (`eks: ["k8s","kubernetes"]`, `api_gateway: ["apigw"]`) attached to entries as `aliases` at load time.
  `scoreEntry` already reads `entry.aliases` (`src/core.mjs:55`).
- **Pros:** fixes every "empty result" case. Deterministic and reviewable.
- **Cons:** manual upkeep.
  - Term maps are vendor-blind: `k8s→kubernetes` cannot say "for AWS, EKS". Today that leaves EKS at rank 7.
  - Entry-keyed aliases must survive catalog regeneration. `catalog/aws.json` is overwritten by
    `scripts/ingest_index.py`, and `build_pack.py:159-162` drops unknown fields. So the aliases must live
    **outside** the generated catalogs and be merged in `loadCatalog`.
- **Verdict:** required. Nothing else invents "apigw" or "gcs".

### (b) Normalization
Lowercase/NFKD is already done (`src/core.mjs:43-49`). Add these:
- **Vendor-word extraction:** `aws, amazon, azure, microsoft, gcp, google` become a **pack boost/filter**
  instead of scored tokens. This fixes `aws k8s` (EKS at rank 28) and `azure postgres` (`azure_batch_ai`
  noise). Do not strip `cloud`; it is meaningful (`cloud sql`, `cloud nat`).
- **Compact equality:** compare with spaces removed on both sides (`api gateway` = `apigateway`, `postgre sql`
  = `postgresql`). This exists for the name only (`:59`); extend it to label and aliases.
- **Light plural/stem:** strip a trailing `s` on tokens longer than 3 characters when the bare form is in the
  vocabulary (`functions`→`function`). Never stem tokens of 3 characters or fewer (`ecs`, `efs`, `sqs`).
- **Name-family prefixes:** the Azure/GCP names repeat the vendor (`azure_azure_cosmos_db`). Matching on
  `label` already avoids this, so no data change is needed.
- **Pros/cons:** cheap. Fixes the vendor noise. Alone it does nothing for shorthand or typos.

### (c) Token/prefix matching and tiered ranking (replaces substring scoring)
- Score each query token by its **best** tier against word tokens of name, label, aliases, and tags.
- **Order:** exact entry name/label > exact alias > whole-word in name/label > word-prefix in name/label >
  whole-word in tags > fuzzy.
- Mid-word substring counts only for terms of **≥ 4 characters**, as in draw.io.
- Keep the head-noun boost (`src/core.mjs:68-72`) and its tests.
- **Pros:** removes the `lb`→lightbulb and `nat`→alter**nat**e false positives. Makes exact matches always win.
- **Cons:** rebalancing scores can shift existing rankings. Pin the current good cases (s3, lambda, nat
  gateway, gateway vpc endpoint) as regression tests first.

### (d) Typo tolerance: edit distance or trigrams
- **Damerau-Levenshtein** (transpositions count as 1 edit) against the vocabulary, applied only to tokens that
  got **no** non-fuzzy hit:
  - Max distance 1 for 5–8 characters, 2 for 9+ characters, **0 for ≤4 characters**.
  - Measured: `kubenetes`→{kubernetes}; `elasticsearh`→{elasticsearch}; `dynamdb`→{dynamodb, dynamo};
    `postgress`→{postgresql, postgre, postgres}.
  - Without the ≤4 guard: `es`→{ecs, efs, eks, ms, os, as}, `pg`→{pc, p2, p3, p4, 5g, py}, `lb`→{db, lab},
    `s3`→9 tokens. That shows why short tokens must never be fuzzed.
- **Trigram/Dice:** better for long, multi-word typos, but weak on short service names. Edit distance with a
  length guard is enough here.
- **Soundex** (what draw.io uses): free phonetic recall, but coarse (`kubenetes` and `kibana`-style
  collisions). Not needed if edit distance is used.
- **Pros:** fixes the `kubenetes` → `[]` case. About 20 lines, no dependency, ≈2 ms.
- **Cons:** can surface wrong near-neighbours. Must rank strictly below every non-fuzzy tier and only run as a
  fallback.

### (e) Small libraries
**Fuse.js** 7.5.0 (Apache-2.0, 0 dependencies, ~417 KB unpacked; npm registry):
- Bitap-based approximate matching ([src/search/bitap](https://github.com/krisk/Fuse/tree/edf2fb608eca0461508d1d71317e6e58309ffada/src/search/bitap)).
- Defaults `threshold: 0.6`, `location: 0`, `distance: 100`, `ignoreLocation: false`, `minMatchCharLength: 1` ([src/core/config.ts L4-36](https://github.com/krisk/Fuse/blob/edf2fb608eca0461508d1d71317e6e58309ffada/src/core/config.ts#L4-L36)).
  - The default location/distance penalize matches far from the start of a field, which is a bad fit for long
    tag strings unless `ignoreLocation` is turned on.
  - The 0.6 threshold is loose, so short queries like `es` match nearly everything.
- No synonym support, so you still need (a).

**MiniSearch** 7.2.0 (MIT, 0 dependencies, ~826 KB unpacked):
- Inverted index with BM25+, `prefix`, and `fuzzy` (≥1 means max Levenshtein distance; 0–1 means a fraction of
  term length, capped by `maxFuzzy`, default 6).
- Per-field `boost`. Default weights `{ fuzzy: 0.45, prefix: 0.375 }` relative to exact = 1.
- `processTerm` can return several terms, which is the documented hook for synonyms (e.g. `"lbs"` →
  `["lbs","lb","pound","pounds"]`).
- Sources: [SearchOptions docs](https://lucaong.github.io/minisearch/types/MiniSearch.SearchOptions.html), [MiniSearch.ts L2195-2197](https://github.com/lucaong/minisearch/blob/3d239d1c3ae7aef1bf5d8945dd7b5f0709f646f5/src/MiniSearch.ts#L2195-L2197).
- The best fit of the two. But it adds the kit's **first runtime dependency** and still needs the curated alias
  data. At 2k documents, its index buys nothing over a linear scan.

**Verdict:** do not add a library. The hard part is the alias data and the ranking tiers, and both are
repo-specific. Each library would replace about 40 lines of scoring at the cost of breaking the zero-dependency
rule.

### Pitfalls
- **Short aliases** (`es`, `pg`, `lb`, `db`, `ai`): never substring- or fuzzy-match them. Use them only as
  **exact whole-token** alias hits. Today `es` as a raw substring would hit 499 entries.
- **Ambiguity across clouds:** `k8s` means EKS, AKS, GKE, and the OSS tile. `postgres` means RDS, Azure DB for
  PostgreSQL, Cloud SQL, and OSS. `cache` means ElastiCache, Azure Cache, and Memorystore. `es` means AWS
  OpenSearch Service and OSS Elasticsearch/OpenSearch.
  - Entry-keyed aliases handle this naturally: all of them match, and the vendor token or the skill's domain
    decides.
  - A term map that rewrites `es → elasticsearch` hides OpenSearch (seen above).
- **Replace vs expand:** the current replacement loses the literal term (`pg` → `postgresql` drops `postgres`).
  Aliases should **add** alternatives, matched with OR inside the token slot.
- **Ranking order must be strict:** exact > alias > prefix > fuzzy. Otherwise an alias hit like
  `es`→`elastic_beanstalk` (via the "elastic" prefix) could outrank the real thing.
- **Generated-data overwrite:** do not hand-edit `catalog/aws.json`. The generator rewrites it (`scripts/ingest_index.py`).
- **Silent empties:** an empty result makes the agent draw a plain box (commit `3be6034` message). A fuzzy
  fallback reduces this, but the output should flag fuzzy hits (e.g. `match:"fuzzy"` in `--full`) so the agent
  can double-check.

## 5. Recommendation

### Where the alias data lives
- Create **`data/search-aliases.json`**. `data/` is already shipped in `package.json` `files` and holds
  non-catalog inputs (`data/lobe-icons.json`). Do not put it in `catalog/`, because `loadCatalog` would merge it
  as a pack (`src/core.mjs:27-34`).
- **Entry-keyed** shape, one list per catalog name:
  ```json
  {
    "eks": ["k8s", "kubernetes"],
    "azure_kubernetes_services": ["aks", "k8s"],
    "gcp_google_kubernetes_engine": ["gke", "k8s"],
    "kubernetes": ["k8s", "kube"],
    "elasticsearch_service": ["es", "elasticsearch", "opensearch"],
    "elasticsearch": ["es", "elk"],
    "opensearch": ["es"],
    "postgres": ["pg", "psql", "postgresql"],
    "rds_postgresql_instance": ["pg", "postgres", "psql"],
    "azure_azure_database_postgresql_server": ["pg", "postgres"],
    "gcp_cloud_sql": ["postgres", "mysql", "pg"],
    "api_gateway": ["apigw", "apigateway"],
    "dynamodb": ["ddb", "dynamo"],
    "elastic_load_balancing": ["elb", "alb", "nlb", "load balancer"],
    "gcp_cloud_storage": ["gcs"],
    "managed_streaming_for_kafka": ["msk"],
    "azure_virtual_networks": ["vnet"],
    "mongodb": ["mongo"], "rabbitmq": ["rabbit"]
  }
  ```
  All 19 target names in this sample were checked against `catalog.validNames` (all present at commit 1a03d87).
- `loadCatalog` merges these into `entry.aliases`. A test asserts **every key is a real catalog name**
  (`catalog.validNames`), so a regeneration that renames an icon fails CI instead of silently dropping the alias.
- Migrate the 7 `QUERY_ALIASES` entries into this file and delete the map (`src/core.mjs:75-80`).
- Optionally let pack manifests carry `aliases` too: that is a one-line passthrough in `build_pack.py:162`. The
  data file alone is enough.

### Matching and ranking (in `searchIcon`/`scoreEntry`, zero dependencies)
1. Normalize the query (existing `norm`). Pull vendor tokens `aws|amazon|azure|microsoft|gcp|google` out as a
   **pack preference**: boost entries whose `pack` matches, without filtering, so OSS tiles still show. If the
   query is *only* a vendor word, keep the current behavior.
2. For each remaining token, take the best tier per entry:
   - **T0 exact:** the whole query equals the name or label, compared both normally and with spaces removed.
   - **T1 alias:** the token (or the whole query) equals an alias exactly.
   - **T2 word:** whole-word match in name or label.
   - **T3 prefix:** the token is a word-prefix in name or label. Mid-word substring only if the token has ≥ 4
     characters (as in draw.io).
   - **T4 tags:** whole-word or prefix match in tags/category.
   - **T5 fuzzy:** Damerau-Levenshtein ≤1 (5–8 characters) or ≤2 (9+) against the vocabulary, **only for tokens
     with no T0–T4 hit**, and never for tokens of ≤4 characters.
   - Tier weights must be widely separated (for example 1000/400/100/50/20/5) so a lower tier can never beat a
     higher one through repetition.
3. Keep the head-noun boost and the `kind`/`category` filters. Add `match: "<tier>"` to `--full` output.
4. In the domain skills (step 3), add one line: *"Prefix queries with the cloud (`aws k8s`, `gcp postgres`)
   when shorthand is ambiguous."*
5. Fix the stale `search_icon` text in `src/builder.mjs:57,77` to say `drawio-ai search`.

Estimated size: about 80–120 lines in `src/core.mjs`, about 100 lines of JSON, and about 15 tests. No new files
under `src/`.

### Minimal `node:test` list (`test/core.test.mjs`)
- `k8s` → contains `kubernetes`, `eks`, `azure_kubernetes_services`, `gcp_google_kubernetes_engine`.
- `aws k8s` → `[0].name === "eks"`. `azure k8s` → `[0]` is `azure_kubernetes_services`. `gcp k8s` and `gke` →
  `[0]` is `gcp_google_kubernetes_engine`.
- `aks` → contains `azure_kubernetes_services`.
- `es` → contains `elasticsearch`, `opensearch`, and `elasticsearch_service`. Also, no result outside the
  search/analytics family appears in the top 5 (e.g. none of `elastic_beanstalk`, `ecs`, `efs`).
- `postgres`, `postgresql`, `pg` → each contains both `postgres` and `rds_postgresql_instance`.
  `aws postgres` → `[0]` is an RDS PostgreSQL icon.
